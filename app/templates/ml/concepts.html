ML Concepts — Study Guide

All 3 syllabus modules explained with simple language and Chai House examples.

What it is: Choosing the best algorithm for your problem — like choosing between a simple recipe and a complex one.

Chai House Example: Should we use Simple Linear Regression (predict tomorrow's Regular Tea sales from yesterday's trend) or SVR (using many features like day of week, lag values)? We compare them on test data to decide.

How we do it: See the Model Comparison page — all 6 regression models are evaluated side by side.

Overfitting: The model memorizes training data perfectly but fails on new data. Like a waiter who remembers only last Tuesday's exact orders — useless for today.

Underfitting: The model is too simple to capture patterns. Like predicting "same sales every day" — ignores weekends, seasons, etc.

Chai House Example: Polynomial Regression (degree=3) shows this! On our comparison table, its Test MAE spikes to ~35 cups while Train MAE is low — a classic overfitting signature. Compare to Ridge/Lasso which generalize better.

Overfit: Train MAE ≈ 1, Test MAE ≈ 35 ← BAD
Good fit: Train MAE ≈ 3, Test MAE ≈ 3 ← GOOD

Bias: Error from wrong assumptions (underfitting). High bias = consistently wrong.

Variance: Error from sensitivity to training data (overfitting). High variance = right on training, wrong elsewhere.

Total Error = Bias² + Variance + Irreducible Noise

Chai House Example: Simple Linear Regression has high bias (assumes demand grows linearly). Polynomial degree=3 has high variance (wiggles to fit every training point). Ridge/SVR balances both.

Regularization: A penalty added to the model to prevent large coefficients (overfitting). Like adding a "budget limit" on how complex the model can be.

Hyperparameters: Settings you choose before training. alpha in Ridge/Lasso, C and kernel in SVM are hyperparameters.

Chai House Example: Ridge regression with alpha=100 says "keep coefficients small" — good for our small dataset. We tune alpha using GridSearchCV and pick the best value from [0.01, 0.1, 1, 10, 100].

What it is: Instead of one train/test split, we split data K times and average the results. Gives a more reliable estimate of model performance.

TimeSeriesSplit: For sales data, we CANNOT randomly shuffle — future data would leak into past. TimeSeriesSplit always trains on past data and tests on future data.

Chai House Example: We use TimeSeriesSplit(n_splits=5). Fold 1 trains on days 1–72, tests on 73–90. Fold 5 trains on days 1–360, tests on 361–450.

CV MAE = mean([fold1_mae, fold2_mae, ..., fold5_mae])

Formula: y = β₀ + β₁x + ε

Chai House: Predict tomorrow's Regular Tea cups (y) from 7-day rolling average (x). One predictor, one line.

Coefficient Estimation: We minimize Sum of Squared Residuals using Ordinary Least Squares (OLS): β = (XᵀX)⁻¹Xᵀy

Assumption check: Linearity, independence, homoscedasticity, normality of residuals.

Formula: y = β₀ + β₁x₁ + β₂x₂ + ... + βₙxₙ + ε

Chai House: Predict cups sold using ALL features: day_of_week, month, is_weekend, lag_1, lag_7, rolling_7_mean, etc.

Matrix form: y = Xβ + ε where X is the feature matrix, β is the coefficient vector.

What it is: Add polynomial terms (x², x³) to capture non-linear patterns.

Chai House: Sales might dip in the middle of the month — a curve fits better than a line. Degree=2 adds x² terms. We compare degree=2 vs degree=3.

Warning: Degree=3 massively overfits our dataset — Test MAE = 35 vs Train MAE ≈ 2. This is shown on the Model Comparison page.

Formula: Loss = RSS + α × Σβᵢ²

Effect: Shrinks coefficients toward zero but never to exactly zero. Good when all features are relevant.

Geometric intuition: The L2 penalty creates a circular constraint in coefficient space. OLS solution intersects this circle at a point with smaller coefficients.

Chai House: Ridge with alpha tuned via GridSearchCV gives Test MAE ≈ 2.64 — very competitive with SVR.

Formula: Loss = RSS + α × Σ|βᵢ|

Effect: Can shrink coefficients to EXACTLY zero → automatic feature selection!

Geometric intuition: L1 penalty creates a diamond-shaped constraint. The corner of the diamond is likely to intersect the OLS ellipsoid, setting some β = 0.

Chai House: Lasso may zero out less-important features like day_of_month, keeping only the most predictive ones.

Goal: Find a line/plane that separates classes with the MAXIMUM margin.

2D hyperplane: A line w₁x₁ + w₂x₂ + b = 0

3D hyperplane: A plane w₁x₁ + w₂x₂ + w₃x₃ + b = 0

Chai House: We classify each day's sales as Low/Medium/High demand. SVM finds the boundary that best separates these classes in feature space (day of week, rolling average, etc.).

Hard margin SVM: No points allowed inside the margin. Only works if data is linearly separable.

Soft margin (C parameter): Allows some points to violate the margin. C controls this:

  • Large C → narrow margin, fewer violations (may overfit)
  • Small C → wide margin, more violations allowed (may underfit)

Slack variables (ξ): Each misclassified point gets a slack variable ξᵢ ≥ 0 measuring how far it violates the margin.

Objective: Minimize ½‖w‖² + C × Σξᵢ subject to yᵢ(wᵀxᵢ + b) ≥ 1 − ξᵢ

Chai House: Our SVM uses C=100 (tight margin, precise classification). Found by GridSearchCV. Accuracy = 77.1% on test data.

Our results (from actual training):

  • Accuracy: 77.1%
  • Precision: 78.4%, Recall: 77.1%, F1: 76.9%
  • Best kernel: linear (with C=100)
  • Demand thresholds: Low ≤ 15 cups | Medium 15–22 | High > 22

Support Vector Regression (SVR): Extends SVM to regression. Instead of a margin, SVR tries to fit as many points within an ε-tube as possible.

SVR with rbf/linear kernel and tuned C, epsilon achieves MAE ≈ 2.59 cups — the best regression result in our comparison.
